# 社区服务负荷预测与排班情景

用于估计网格服务需求及具备相应技能的值守能力，并给出可解释的排班情景。全部人员、班次与到件资料均为合成记录。

`fixtures/` 保存 UTF-8 合成业务资料，字段、关系和时间含义见 `DATA.md`。

## 运行

```bash
python3 -m app.server            # http://127.0.0.1:8765
python3 -m unittest discover -s tests -v
```

仅使用 Python 3.11 标准库，无需安装依赖。可选参数：`--host`、`--port`、`--data fixtures`、`--state .state/state.json`。

运行时状态（到件修订、保存的情景、已确认班表）写入 `.state/state.json`；删除该文件可回到初始状态。分析结果不会写回 `fixtures/`。

## 主要口径

| 主题 | 处理方式 |
| --- | --- |
| 到件修订 | 撤销 / 转派 / 补录先于一切计算生效，原始到件记录保留可追溯；扣减为负会直接报错。 |
| 历史基线 | 取起始周之前、资料中实际出现过的最近 N 周，按近因加权平均。缺失周不等于零。 |
| 录入延迟 | 默认按区间处理：低值剔除 `entered_late`，高值保留全部；可切换为全部保留/全部剔除。不声称能区分业务高峰与补录。 |
| 零与未知 | 真实录入的 0 才计为 0，且降低置信度；历史窗口内无记录标记「资料不足」；从未有过记录标记「不可预测」。两者都不按零需求计入合计。 |
| 积压 | 未结事项独立核算，不并入新到件需求；只使用满足新需求后的剩余能力，按情景目标比例消化。`paused` 默认不纳入，可勾选纳入。 |
| 工时 | 按事项类别的分钟/件（低–典型–高）换算，均为显式假设，可在界面调整；未知类别使用通用区间并标注。 |
| 日历/季节 | 应用 `calendar.factor` 时按偏离 1 的幅度附加不确定性；系数是情景输入，不是已验证的因果系数。 |
| 能力 | 按「网格 × 技能」核算。班次扣除休息；同一人员跨网格重叠时段只计一次并列为冲突；资质按有效期判断；同一人多技能时不把能力相加，而按需求比例分摊。 |
| 缺口 | 需求区间与能力区间比较，输出低/典型/高三档。某技能无人可派时列「无人可派」，缺口等于全部需求，不被其他技能的空闲时数抵消。 |
| 已确认班表 | 确认需要显式操作，保存输入指纹；资料或情景变化只更新建议并给出新增/移除/时数变化差异，绝不静默改写已确认内容。 |

界面的「本次建议依赖的假设」逐条列出以上口径，并标注来源为假设、推算或政策。

## 目录

```
app/
  analytics.py   预测、能力核算、积压目标、排班分摊、班表差异
  config.py      情景参数、默认工时假设、校验
  data.py        资料读取、校验、跨表一致性检查
  weeks.py       ISO 周与时间解析
  server.py      HTTP API 与状态存储（标准库 http.server）
  static/        单页界面（无构建步骤）
fixtures/        合成资料
tests/           单元测试与资料结构检查
```

## 可选资料：到件修订

若 `fixtures/arrival_adjustments.json` 存在，会与运行时修订合并应用（按 id 去重）。字段：
`id, kind(cancel|transfer|supplement), grid, week, category, count_delta, to_grid?, note?`。
转派会同时从原网格扣减、向 `to_grid` 增加。更推荐通过界面或 `POST /api/adjustments` 添加，便于留痕。

## API 摘要

- `GET /api/bootstrap`：资料目录、可选周、默认工时、当前状态
- `POST /api/analyse`：`{scenario}` → 预测、能力、覆盖、积压、排班、差异、假设
- `POST /api/adjustments` / `DELETE /api/adjustments/{id}`：到件修订
- `POST /api/scenarios` / `DELETE /api/scenarios/{id}`：保存的情景（最多 8 个）
- `POST /api/plan/confirm` / `DELETE /api/plan/confirmed`：确认/清除班表

## 已知限制

- 区间来自经验幅度与情景假设，不是统计置信区间；没有足够历史时不拟合模型。
- 资质有效期只判断是否覆盖整周；仅部分覆盖的资质会标注提醒，但未细分到具体可用日期。
- 「缺口所需增派」只给时数与 8 小时参考班次数，不虚构人员；新增班次仍需人工核对技能与不跨点约束。
- 日历系数不区分节假日、季节与临时活动的不同机制，只作为可调整的乘数与不确定性。
